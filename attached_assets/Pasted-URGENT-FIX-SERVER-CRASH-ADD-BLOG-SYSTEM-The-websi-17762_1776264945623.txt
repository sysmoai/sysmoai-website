PHASE 1 — DIAGNOSE & FIX THE SERVER CRASH
═══════════════════════════════════════════

1. Check the error logs:
   cd ~/workspace/artifacts/sysmoai-website
   cat dist/api-server/index.mjs | head -50
   
2. Check if the server entry point exists:
   ls -la dist/api-server/
   ls -la artifacts/api-server/

3. Check package.json for the start script:
   cat package.json | grep -A5 "scripts"

4. The error "signal: terminated" usually means:
   a) The server runs out of memory → Fix: reduce bundle size
   b) The port is already in use → Fix: kill existing processes
   c) The entry file path is wrong → Fix: correct the path
   d) Missing environment variables → Fix: add them

5. Try running the server manually to see the actual error:
   cd ~/workspace/artifacts/sysmoai-website
   node dist/api-server/index.mjs

6. If it's a Vite/React SPA (no server needed), check if the
   deployment is wrongly configured as a server app instead of
   static site. For a React SPA:
   - Build should output to dist/public/
   - Deployment type should be "static" not "server"

7. Check .replit config:
   cat .replit
   
   If it references api-server but this is a static React app,
   change the run command to serve the static files:
   
   [deployment]
   run = ["npx", "serve", "-s", "dist"]
   
   OR for the existing setup, make sure the static handler
   path matches the actual build output directory.

FIX the crash. Verify the site loads at the preview URL.
Report the exact error and what you changed.
